## Fresh-OS restore

1. Verify exact target, owner/release/manifest identities, available recovery keys, both ciphertext and reference-image hashes. Run `recheck_backups.py` to authenticate every archive entry on both off-host systems. Do not erase the only recoverable copy.
2. Fence every included cell, stop brokers/observers and all application writers, acquire lifecycle locks and confirm no native active tasks or enabled schedules. Keep retired QA3/QA4 archived and inactive.
3. Use the reviewed `provider_rebuild.py` prepare/rebuild flow only for a newly reviewed plan. It pins the target, validates cloud-init, provisions deploy SSH/sudo and a pinned host key, and refuses automatic resubmission after uncertainty. **Do not replay the already-completed plan.** For an uncertain API submission, inspect the persisted action and reconcile with `resume`; never blindly POST another rebuild.
4. Prove provider action success, changed boot, empty Docker and absent old installation before restoring. Hetzner preserved machine-id in this exercise; machine-id change is not used as fake proof of reinstall. Provision overlay2 explicitly before importing images; Docker's alternate containerd store is not interchangeable with the qualified store.
5. Use the reviewed archive reader, not the older prototype embedded in the archive. Extract to a new private staging directory, authenticate and verify every entry, and preserve POSIX metadata/hardlinks. Failed staging has no accepted marker and must not be activated. Arbitrary ACL/xattr-bearing sources are unqualified; this source had none.
6. Run the guarded `restore_dsh2.py plan --stage …`, `apply --stage … --previous-boot-id …` and `activate --reference-image …` coordinator stages with their required reviewed inputs. Re-enroll only the validated legacy bootstrap identity with `reenroll_legacy_identity.py`, then apply the signed canonical-identity host-operations release. Never bypass an ownership failure. Source observer UID 999 mapped to new observer UID 995; GID 983 was retained. Native/container data ownership is not recursively rewritten.
7. `reference_restore.py` reconstructs the separate fixture with verified image/labels, original resource/security settings, same private address/alias and a late-bound backend host mapping. Empty stopped-container IP fields are not treated as portable identities. Docker's omitted OOM-disable flag is normalized to its equivalent false value, not an OOM-policy relaxation.
8. Run `check_live_restore.py`. Require all seven healthy services, preserved owner/core secrets, native identities/session bindings/paused schedule, original customer login and isolation, original receipt readability, deduplicated original request and zero new task/effect. Compare seven logical databases and original archive fingerprints; do not open the off-host extraction for writing.
9. Credential expiry is preserved, not bypassed. The original application credential expired during this exercise. `renew_fixture_credential.py` first proves that exact credential is expired, then uses the original owner's authenticated API to issue a replacement for the **same application**. It does not recreate accounts, edit auth tables, extend the old expiry or change the clock. Keep that receipt distinct from the preserved core/TLS secret claim. Renew expired browser sessions through normal OIDC too.

## Signed host-operations update and recovery

- Trusted key provisioning is out-of-band under `/etc/alica-release-trust/`. Signing keys remain on Elio, never DSH2/Git. Check scope, validity, revocation, exact predecessor, all artifact bytes and the durable anti-replay state. A release digest is not a substitute for authentication.
- `build_ops_release.py` builds from a clean committed Doghouse checkout. `update_ops.py apply --bundle … --envelope …` verifies the complete candidate, actual host compatibility, exact-source mapping and current runtime ownership **before** quiescence or executing candidate code. Do not run Python with assertions disabled.
- This supported installation has one controlled reference client and no active native work. Keep other clients/owners from submitting work during maintenance. General multi-client production ingress draining is not qualified here.
- Updater holds lifecycle/install/writer locks, stops services and the fixture, snapshots **eight cold code/data paths**, verifies byte/ownership/mode fingerprints, copies the verified candidate privately, validates schema/logical data and real service health, then commits durable authority state.
- An interrupted complete-snapshot transaction stays stopped/fenced. Run `update_ops.py recover` explicitly. It verifies the complete cold preimage before destructive restoration and restores **code AND data**. Recovery keeps lifecycle locks through service/observer restart. Do not reduce `highestAttempt` after rollback: failed signed attempts remain consumed.
- No complete preimage, corrupt preimage, unexpected destination/owner, unsupported schema or uncertain phase means **stop and use operator/off-host recovery**. Never replace a failure with a binary-only downgrade or clear a fence merely to make health green.
- Qualified interruption is a real process exit after candidate installation. Arbitrary power-loss/host-reboot behavior of the local updater is not claimed; OS-loss recovery uses the independently verified off-host restore path. Do not reboot/start units to bypass an incomplete update.
- Observed tests: genuine stopped-container health rejection, process exit before commit, and a real schema change in the existing MemoryV4 database. All restored byte-identical cold preimages and unchanged logical/schema state. A final additional interruption exercised the integrated mapping/version gates and lock-held recovery path.

## Declared predecessor migration

`migration_check.py` derives the original owner/application/native task/session identities, application delivery channel and paused schedule from the verified source and live installation. `migration_contract.py` permits only complete, one-to-one preserve mappings. Identity/channel/schedule source collisions and foreign occupied destinations, unverified backups, live work, channel rebinding and unknown predecessors are denied. Negative tests use read-only inventories derived from actual identifiers; they do **not** pretend to mutate a live foreign installation.

The original migration transaction changed legacy host-operations ownership signatures to canonical v2 while preserving business/native state. Evidence retains its legacy preimage and transaction identity. General renaming, channel reassignment, enabled schedules, foreign-owner merges, new native inventory beyond the declared frozen source, runtime/database upgrades and arbitrary historical snapshots are unsupported. Nonportable OS/container/network identifiers are regenerated; retired cells remain archived. Expired security sessions/grants are renewed normally, not copied into perpetual validity.
