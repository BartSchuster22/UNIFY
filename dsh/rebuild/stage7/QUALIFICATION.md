## Artifact versus execution directory

Python creates interpreter caches when installed CLI modules execute. The signed
archive is immutable; its execution directory may contain those generated files.
Update-base admission extracts a **pristine copy of the original pinned archive**,
uses the unchanged strict signature/inventory verifier, and also checks every
signed deployed member against its declared digest. Generated caches are recorded
separately; they are never admitted as signed artifact members. No file-inventory
exception has been added to the release verifier.

## Evidence and security scope

Private logs, credentials, cookies, plaintext archive extraction, recovery keys and
raw customer exports are not publication artifacts. Public reports contain bounded
results, identifiers, hashes and deliberately synthetic QA material only.
Failed attempts remain in the audit history even when the harness is corrected.
Recovery helpers refuse wrong hosts/cells, changed ownership, active native work,
unverified extraction and unsupported mappings. Original trees remain quarantined.

Production routes and development workloads are outside this qualification. QA
signatures are not production trust. Physical backup erasure, elapsed multi-day
retention and wider production/SBOM/licensing gates are not inferred from these tests.
